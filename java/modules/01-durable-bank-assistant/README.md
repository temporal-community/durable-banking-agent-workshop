# Module 1 (Java): A Durable Bank Assistant

A plain bank-assistant activity that calls OpenAI, invoked from a Temporal workflow. No tools yet,
one LLM call, and already durable.

## Architecture

- `BankAssistantActivities`/`BankAssistantActivitiesImpl`: one activity, `answerQuestion`, that
  calls the OpenAI chat completions API.
- `BankAssistantWorkflowImpl`: calls that activity through a stub built with
  `Workflow.newActivityStub(...)`. That is the whole workflow.
- There's no Java equivalent of Python's `OpenAIAgentsPlugin`, so the activity boundary is written
  by hand instead of generated by a plugin - the lesson is the same, just more visible: wrapping
  the model call in `@ActivityInterface`/`@ActivityMethod` is what makes it retryable, resumable
  Temporal state instead of a plain function call.

## What to notice

Open the Temporal Web UI and look at the event history. `answerQuestion` is its own activity, with
its own retry policy, scheduled and completed like any other. The workflow code has no retry logic
in it - that comes from the activity boundary itself, by default.

The assistant has no tools, so ask it anything account-specific and it can't actually look
anything up. Module 2 gives it a real tool.

## Prerequisites

- Java 17+
- [Maven](https://maven.apache.org/)
- [Temporal CLI](https://docs.temporal.io/cli)
- `OPENAI_API_KEY` in your environment

## Run it

```bash
temporal server start-dev          # once, in its own terminal
cd exercise
```

Fill in the `TODO` in `BankAssistantWorkflowImpl.java`, then:

```bash
mvn -q compile exec:java -Dexec.mainClass=bankworkshop.module1.Worker           # terminal 2, stays running
mvn -q compile exec:java -Dexec.mainClass=bankworkshop.module1.StartWorkflow \
    -Dexec.args="What is my account balance?"                          # terminal 3
```

Stuck? Compare with `solution/`.

Task queue: `durable-bank-assistant-tq-java`.
